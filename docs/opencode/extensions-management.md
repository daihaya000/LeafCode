# OpenCode 拡張機能管理仕様

## 目的

設定画面から OpenCode 本体の Skills、MCP サーバー、プラグインを一覧し、有効・無効を切り替えられるようにする。WebUI 独自の「アドオン」とは別の「拡張機能」タブで扱う。

## 対象と非対象

- 対象: グローバル設定ディレクトリ（`~/.config/opencode`）の Skills、`opencode.jsonc` の MCP と設定済みプラグイン、同ディレクトリの自動読込ローカルプラグイン。
- 非対象: プロジェクト固有・同梱・外部ディレクトリの Skills、MCP の追加・編集・認証、プラグインのインストール・削除。
- OpenCode プロキシ経由の設定書込みは引き続き禁止し、WebUI のサーバー API だけが設定ファイルと拡張機能ディレクトリを操作する。

## 画面

`SettingsView` に「拡張機能」タブを追加する。タブには次の3セクションをこの順で表示する。

1. **Skills**: 名前、説明、状態、有効/無効スイッチ。
2. **MCP サーバー**: 名前、接続情報、状態、有効/無効スイッチ。
3. **プラグイン**: 名前、種別、状態、有効/無効スイッチ。

各行は既存の設定リスト行と同じカード表示にし、スイッチは `role="switch"`、`aria-checked`、操作内容を示す `aria-label` を持つ。操作中は該当行だけを無効化して `aria-busy` を付ける。色だけで状態を伝えず、状態バッジには「有効」「無効」「接続中」「接続失敗」「要認証」などのテキストを必ず表示する。

初回取得中はセクションごとのローディング表示、空の場合は対象の配置・設定先を示す空状態、取得・変更失敗時は再試行できるエラー表示とする。モバイルでは副情報を省略・折返し可能にし、名前とスイッチを常に優先表示する。

変更成功後は3セクション共通の「OpenCode を再起動」バナーを表示する。既存のホスト再起動 API を使い、再起動後に全一覧を再取得する。ホストを利用できない場合は再起動ボタンを無効化し、トレイホスト経由で再起動する必要がある旨を表示する。

## Skills

- 一覧は `skills/` と `skills-disabled/` を再帰走査し、`SKILL.md` を含む直属のスキルディレクトリを表示する。OpenCode の `/skill` 応答が利用できる場合は説明文をマージする。
- `skills/<name>` は有効、`skills-disabled/<name>` は無効として表示する。
- 無効化は `skills/<name>` を `skills-disabled/<name>` へ、有効化は逆方向へ安全に移動する。
- 操作対象名は正規のスキルディレクトリ名に限定し、解決済みパスが許可された親ディレクトリ配下であることを検証する。移動先の同名ディレクトリが存在する場合は失敗として元を保持する。
- プロジェクト固有、同梱、または外部パス由来の Skills は状態のみ表示し、スイッチは表示しない。

## MCP サーバー

- 一覧の正はグローバル `opencode.jsonc` の `mcp` オブジェクトとする。実行状態は OpenCode の `/mcp` 応答をマージする。
- `enabled: false` は無効、それ以外は有効として扱う。切替は対象エントリの `enabled` だけを書換える。
- 実行状態は、接続中・接続失敗・要認証・無効・エンジン停止中を表示する。設定と実行状態が再起動待ちで不整合の場合は「再起動で反映」と表示する。
- JSONC のコメントと書式を可能な限り保持できる JSONC 編集器を使用し、設定全体を JSON として再シリアライズしない。書込みは原子的に行う。

## プラグイン

プラグインには設定済みとローカル自動読込の2種があるため、どちらも一覧・切替対象とする。

- `opencode.jsonc` の `plugin` 配列の各要素は「設定済み」として表示する。無効化時は要素を配列から取り除き、WebUI 専用のローカル状態ファイルに元の値と順序を保存する。有効化時は保存値を元の順序に復元する。
- `plugin/*.js` と `plugin/*.ts` は「ローカル自動読込」として表示する。無効化時は `plugin/` から `plugin-disabled/` へ移動し、有効化時は逆方向へ移動する。
- 設定済みプラグインの無効状態は WebUI のローカル管理情報であることを表示し、手動で `opencode.jsonc` を変更した場合は再読込時に設定ファイルを正として整合させる。
- パス型プラグインと npm 指定、タプル形式のプラグイン値を識別・保持し、表示名は安全な文字列化で生成する。プラグイン本体の内容は実行・評価しない。
- ディレクトリ移動は Skills と同じパス検証・衝突時失敗・原子性の原則に従う。

## API と安全性

- WebUI サーバー内に専用 API を設け、Skills、MCP、プラグインの一覧取得と単一項目の切替だけを公開する。
- クライアントから任意パス、任意コマンド、任意の設定断片を受け取らない。ID はサーバーが一覧で発行した識別子だけを受け、各操作で再検証する。
- 設定ファイルの読書き・状態ファイル書込み・ディレクトリ移動はエラーを利用者向けに安全な文面へ変換する。秘密値を API 応答・ログ・UIへ返さない。
- 並行操作による設定上書きを避けるため、設定ファイルへの更新は同一プロセス内で直列化し、書込み前に再読込する。

## 受入条件

1. 無効なグローバル Skill を UI から有効化すると `skills-disabled/<name>` が `skills/<name>` へ移動し、UI は有効と再起動要求を表示する。
2. 有効なグローバル Skill を無効化すると逆方向へ移動し、同名衝突時はファイルを失わずエラーを表示する。
3. MCP の `enabled` を UI から切り替えると、他の JSONC 内容を破壊せず対象値だけが更新される。
4. 設定済み・ローカル自動読込の両プラグインが一覧に出て、どちらも有効/無効を切り替えられる。
5. いずれの変更後も OpenCode 再起動要求が一つだけ表示され、再起動完了時に一覧を更新する。
6. 無効化できないスキルの種別、取得失敗、空状態、操作中、再起動不可が画面と支援技術に明確に伝わる。
