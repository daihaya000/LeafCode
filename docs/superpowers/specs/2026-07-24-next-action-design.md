# NextAction 設計仕様

## 1. 目的

タスク詳細の会話履歴から、利用者が次に送ると有益な**1件の指示文**を生成し、フォローアップ composer へ安全に転記できる NextAction 機能を追加する。

目的は、作業が完了・中断・確認待ちになった会話で「次に何を頼めばよいか」を利用者が考え直す負担を減らすことである。提案の閲覧・転記だけでは OpenCode セッションへメッセージを送信しない。

対象は `/task/[id]` の既存セッションに限定する。ホームの新規タスク composer、子セッション、会話履歴のないタスクは対象外とする。

## 2. 利用者フロー

1. セッションが読み込まれ、実行中・権限確認・質問待ちでないとき、フォローアップ composer の上に `次の指示を提案` ボタンを表示する。
2. 利用者がボタンを押すと、現在のセッションの可視会話履歴を材料にサーバーが提案を1件生成する。
3. 生成中は同じ位置にスピナーと `提案を作成中…` を表示し、重複実行を防ぐ。
4. 成功時は提案本文と `入力欄に入れる`、`再生成` の操作を表示する。
5. `入力欄に入れる` は提案全文で既存 composer の内容を置き換え、textarea にフォーカスする。送信は利用者が既存の送信操作で明示的に行う。
6. `再生成` は同じ会話履歴を再評価して1件だけ置き換える。以前の提案は保存しない。
7. 失敗時は composer の既存エラー表示と同じトーンのインラインエラー、`再試行` を表示する。入力中の本文・添付・選択中のモデル等は変更しない。

## 3. 提案内容の要件

- 提案は日本語の、実行可能な1件のユーザー指示文とする。説明、前置き、複数候補、Markdown見出しを含めない。
- 最新の会話で未回答の質問・未解決の失敗・残存 ToDo があれば、それを最優先する。
- 明確な次工程がない場合は、直近の成果の確認、テスト、レビュー、コミットなど、会話の目的に沿う最小の次工程を提案する。
- 存在しない結果や実行済みと確認できない事実を前提にしない。
- 提案生成専用の一時セッションにはツール実行を許可しない。ファイル変更・シェル実行・ネットワーク操作・権限要求を発生させない。
- 元のセッションに提案生成用のユーザー/assistantメッセージを追加しない。

## 4. API と生成方式

`POST /api/tasks/[id]/next-action` を追加する。

リクエストは、表示中タスクの `sessionId`、必要なら現在 composer で選択されている `model` と `agent` を受け取る。サーバーはタスク所有の workspace と session を検証し、OpenCode から会話履歴を取得する。クライアントは会話本文を送らない。

サーバーは次の手順で提案を生成する。

1. 可視会話履歴（巻き戻し済みメッセージを除く）を時系列順のテキストとして整形する。本文は安全な上限までに制限し、直近メッセージを優先して残す。
2. 同じ workspace に一時 OpenCode session を作成する。
3. `POST /session/{id}/prompt` を同期呼び出しし、固定 system instruction、整形済み履歴、`tools: {}` を渡す。選択済み model/agent が有効なら引き継ぐ。
4. 返却された assistant text から1件の提案を抽出・正規化して `{ suggestion: string }` を返す。
5. 成否にかかわらず一時 session を削除する。削除失敗はログに記録するが、成功した提案を失敗扱いにはしない。

履歴が空、session がない、またはタスクと session の対応を確認できない場合は `400` を返す。OpenCode の接続・生成失敗は、秘密情報や会話本文をレスポンスに含めず `502` と汎用エラー文を返す。

## 5. UI 仕様

### 5.1 配置と視覚設計

- コンポーネント名は `NextAction` とし、TaskView の composer 内で TodoPanel の直後、既存エラー表示より前に置く。
- composer と同じ `max-w-3xl` に収め、fixed/absolute overlay にしない。会話領域と操作領域を遮らない。
- 未生成時は控えめな secondary button（Sparkles アイコン + `次の指示を提案`）のみとする。
- 提案表示は `border-border`、`bg-surface`、既存の角丸・spacing・text token を用いる。色や余白をハードコードしない。
- 成功表示には小見出し `次の指示` と本文を置き、操作ボタンを本文の下に配置する。

### 5.2 状態

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 未生成 | `次の指示を提案` | 生成開始 |
| 生成中 | spinner + `提案を作成中…` | 生成・再生成・転記は不可 |
| 成功 | 提案本文、`入力欄に入れる`、`再生成` | 転記または再生成 |
| 失敗 | `提案の生成に失敗しました。`、`再試行` | 再試行 |
| 非表示 | 会話未読込、sessionなし、working、permission/question待ち | なし |

生成済みの提案は、会話メッセージが増減・巻き戻し・タスク切替で失効させて未生成状態へ戻す。これにより古い履歴の提案を誤って使わない。

### 5.3 アクセシビリティとレスポンシブ

- すべての操作は semantic button と分かりやすい accessible name を持つ。
- 生成中は領域に `aria-busy="true"`、状態文に `role="status"` を付ける。失敗文は `role="alert"` にする。
- `入力欄に入れる` 後は textarea へフォーカスし、読み上げユーザーが直ちに編集を続けられるようにする。
- モバイルでは提案本文と操作を縦積みにし、ボタンのタップ領域を既存標準以上に保つ。横スクロールを発生させない。

## 6. 安全性・プライバシー

- 会話本文は NextAction API のサーバー内部でのみ取得し、ブラウザのリクエスト本文、エラー、ログへ出力しない。
- 生成に渡す内容は対象 session の会話だけであり、他タスク・他workspaceの履歴を混在させない。
- 一時 session は tools 無効で作成し、処理完了後に必ず削除する。
- 提案は自動送信・自動実行しない。利用者の明示的な転記と既存送信操作を必須にする。

## 7. 受け入れ基準

1. idle かつ会話を持つ TaskView で `次の指示を提案` が表示される。
2. 生成中は重複リクエストできず、他の composer 内容を失わない。
3. API は対象 session の履歴だけを使い、tools 無効の一時 session を使って1件の提案を返し、終了後に削除する。
4. `入力欄に入れる` は提案を textarea に反映してフォーカスするが、`sendPrompt` を呼ばない。
5. 会話更新・巻き戻し・タスク切替で古い提案が消える。
6. OpenCode エラー時は会話本文を露出せず、再試行可能なエラー状態を表示する。
7. 375px、768px、1280px で composer と重ならず、ページ横スクロールを作らない。
8. Vitest で生成 API の入力検証・一時 session の削除・エラー処理、UI の各状態・転記時の非送信・失効を検証する。

## 8. 実装範囲

- `web/src/app/api/tasks/[id]/next-action/route.ts` と対応する route test
- 会話からテキストを安全に抽出・提案を正規化する pure helper と unit test
- `web/src/components/task/NextAction.tsx` と component test
- `web/src/components/task/TaskView.tsx` の状態・composer 接続

既存の通常送信、SlashSuggestMenu、画像添付、モデル/agent 選択、TodoPanel、session stream の仕様は変更しない。
