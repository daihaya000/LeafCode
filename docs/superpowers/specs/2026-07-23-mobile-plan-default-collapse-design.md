# スマホ向けプラン初期最小化 仕様

## 目的

スマホの限られた表示領域でプラン本文が会話を占有しないよう、プランカードを初期状態で最小化する。ユーザーが必要なときに展開し、本文の確認と承認操作を行えるようにする。

## 対象範囲

- `PlanDocumentCard` で表示するすべてのプランを対象とする。
- 承認待ちの最新プランと過去のプランを同じ規則で扱う。
- 既存の `TaskView` の画面幅判定に合わせ、768px未満をスマホ表示とする。
- 768px以上の初期表示は現状どおり展開状態を維持する。

## UIと状態

- スマホ表示では各プランカードを初期最小化する。
- 最小化中もカードのヘッダー、プラン名、開閉アイコンを表示する。
- ヘッダー操作で本文を展開・再最小化できる。
- 最小化中はMarkdown本文と承認ボタンを隠す。
- 展開後は既存どおり本文を閲覧でき、承認可能なプランでは承認ボタンを操作できる。
- 開閉状態は永続化せず、カードコンポーネントの生存中だけ保持する。

## 実装方針

- `TaskView` が既に保持する `isMd` を利用し、`PlanDocumentCard` に初期最小化の指定を渡す。
- `PlanDocumentCard` 内で独自の `matchMedia` 判定は追加しない。
- 初期最小化の指定からカード固有の開閉stateを初期化し、その後のユーザー操作を保持する。
- 開閉UIは既存の折りたたみパターンに合わせ、`aria-expanded` を設定したボタンとして実装する。

## アクセシビリティ

- 開閉操作はネイティブの `button` を使い、キーボードで操作可能にする。
- ボタンに現在の状態を示す `aria-expanded` を付与する。
- 開閉アイコンだけに状態を依存せず、支援技術から展開状態を判別可能にする。

## テストと受け入れ条件

- 768px未満では、承認待ちを含むすべてのプランが初期最小化される。
- 768px以上では、プランが初期展開される。
- ヘッダー操作で本文を展開・再最小化できる。
- 展開時に既存の承認操作が利用できる。
- `aria-expanded` が開閉状態と一致する。
- 既存のプラン読み込み中、読み込み失敗、承認済み表示を壊さない。

## 対象外

- 開閉状態のリロード後・セッション間の永続化。
- ブレークポイント体系の変更。
- プラン本文や承認フロー自体の変更。
