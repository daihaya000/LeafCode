# リモートプロジェクトフォルダ選択

## 背景

LAN/VPN の URL で WebUI を使うと、`/api/browse/folder` と
`/api/browse/dirs` は 403 になる。これらはホストPCのネイティブダイアログと
ファイルシステムを扱うため、loopback 以外に公開すると、ネットワーク上の
第三者がホストのディレクトリ構成を取得し、任意の作業対象を追加できるためである。

リモート利用者にもプロジェクト追加を提供する。ただし、クライアント端末ではなく
**接続先サーバー上**の、管理者が明示的に許可したディレクトリだけを対象にする。

## 前提条件（本体実装の前に必須）

現行の Caddy Basic Auth は任意で、BFF はリモート利用者の主体・権限を識別しない。
したがって、認証済みかつ権限を持つ利用者だけに API を開く仕組みを先に導入する。

- BFF が検証できる認証済み主体と `project:read` / `project:add` 権限を定義する。
- 認証プロキシを使う場合、BFF は直接到達を遮断し、プロキシが付与する署名付きで
  改ざん不能な利用者ヘッダーだけを信頼する。
- 管理者は利用者またはロールごとに「選択可能ルート」を設定する。
  既存の `allowed_roots` をそのまま公開範囲に流用しない。
- 認証・認可・監査ログの仕様が承認されるまでは、LAN/VPN へのフォルダ列挙 API を
  実装しない。loopback 向け既存 API の制限も緩めない。

## 目的

権限を持つリモート利用者が、割り当て済みルートの配下だけを閲覧し、プロジェクト
として追加できるようにする。

## 非目標

- クライアント端末のローカルフォルダ選択
- ネイティブ Windows フォルダダイアログのリモート表示
- ホーム、クイックアクセス、ドライブ直下、UNC、システム領域の列挙
- 任意パス入力による選択範囲の回避

## UX

### 入口と表示

- 既存の「プロジェクトを追加」を維持する。
- loopback では既存のネイティブ選択を「このPCでフォルダを選択」として利用する。
- リモートではネイティブ API を呼ばず、モーダル「サーバー上のプロジェクトを追加」
  を開く。
- 冒頭に「接続先サーバーで管理者が許可した場所のみ表示します。選択したプロジェクトは
  OpenCode の作業対象になります。」を表示する。
- 最初に許可ルートを一覧し、選択後はその配下のディレクトリだけを表示する。
  現在位置はパンくずまたは省略表示する。許可ルートの外への「上へ」は無効にする。
- 現在のディレクトリを「このフォルダを追加」で追加する。手入力欄、クイックアクセス、
  ホーム起点はリモート表示から除外する。

### 状態とアクセシビリティ

- 読み込み中: Spinner と「フォルダを読み込んでいます」、移動・追加を無効化する。
- 許可ルートなし: 「選択できる場所が設定されていません。サーバー管理者に許可ルートの
  追加を依頼してください。」を表示し、追加を無効化する。
- 空: 「この場所に表示できるサブフォルダはありません。」。現在位置が許可範囲なら追加は可能。
- エラー: 一般エラーは「フォルダ一覧を取得できません。再読み込みしてください。」、
  権限外・リンク逸脱は「この場所は選択できません。」とし、範囲外のパスを返さない。
- 成功時は「『{プロジェクト名}』を追加しました。」を通知する。重複は既存プロジェクトを開く。
- 既存モーダルの dialog、フォーカストラップ、Escape、閉じた後の起点へのフォーカス復帰を維持する。
  一覧は `ul/li/button`、ロードと結果は `aria-busy` / `aria-live="polite"` を使う。
- `sm` 未満は下部シート、それ以上は中央モーダル。狭幅では説明、現在位置、一覧、主操作を優先し、
  主操作を常に到達可能にする。

## API とセキュリティ

新しいリモート専用 API を作る。既存 `/api/browse/dirs` は loopback 専用のまま維持する。

- API は認証と `project:read` を必須とし、許可ルート一覧、現在位置、親（許可ルート内のみ）、
  直下の子ディレクトリだけを返す。
- 各要求で、利用者に割り当てられたルートへの所属を `path.resolve` と realpath の両方で確認する。
  シンボリックリンクが範囲外へ出る場合は列挙・追加とも拒否する。
- ルートは管理者設定からのみ取得する。リクエストのパス、`Host`、`X-Forwarded-For` を
  認可根拠にしない。
- プロジェクト追加 API は `project:add` を必須にし、同一の realpath 範囲検証を再実行する。
  列挙済みであることを信頼しない。
- API は利用者ID、操作種別、許可ルートID、結果、時刻を監査ログに残す。拒否時に絶対パスを
  クライアントへ返さない。
- レート制限、CSRF 対策、認証失効時の 401/403、監査ログの保持期間は認証基盤仕様で定義する。

## 受入基準

1. 権限を持つ LAN/VPN 利用者は、403 にならず自分の許可ルートとその配下だけを閲覧・追加できる。
2. 権限のない利用者、未認証利用者、範囲外パス、ドライブルート、UNC、システム領域、
   シンボリックリンク逸脱先は列挙・追加できない。
3. 任意パス入力や API 直呼びでは範囲制限を回避できない。
4. 許可ルートなし、読み込み、空、通信失敗、権限拒否、重複、成功の各状態を上記文言と
   操作可否で確認できる。
5. キーボードだけで開く、移動、追加、閉じる操作ができ、狭幅・広幅とも主操作に到達できる。
6. loopback の既存ネイティブ選択と `/api/browse/dirs` の host-only 制限は回帰しない。
